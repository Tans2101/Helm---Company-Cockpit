Helm — how we use Google Workspace and Google Cloud Console
============================================================

This file is the operator source of truth. It describes what Helm actually
does in code today, which Google product it talks to, which console you
click, and which secrets live on Render. It is not a wishlist.

There are two different Google systems. Do not mix them.

  1) Google Cloud Console  (console.cloud.google.com)
     Project, APIs, OAuth client, API keys, service accounts, Document AI.
     The $300 GCP trial credits live here.

  2) Google Workspace
     The customer's Gmail / Calendar / Drive / Sheets, accessed only after
     they click Connect Google in Helm. Helm never stores Workspace mail
     bodies. Helm the company may also run its own Workspace for helmcontrol.online
     email — that is unrelated to product OAuth.

Clerk Google sign-in is a third OAuth client (Clerk dashboard + Google
Cloud credentials for login). That is identity, not Calendar/Gmail.

---------------------------------------------------------------------------
A. Cloud Console project (Helm operator)
---------------------------------------------------------------------------

Use ONE GCP project for Helm (recommended name: helm-company-cockpit).

Enable these APIs on that project:

  Product OAuth (user Connect Google — billed as Google Workspace APIs,
  not the $300 credits):
    - Google Calendar API
    - Gmail API
    - Google Sheets API
    - Google Drive API
    - Google Picker API   (needed for "From Drive" on Financials)

  GCP trial credits (Helm's own service account, not the customer):
    - Cloud Document AI API
    - (optional later) Vertex AI API — not wired in code yet

OAuth consent screen
  User type: External
  App name: Helm
  Support email: your Workspace / founder Gmail
  Authorized domains: helmcontrol.online
  Scopes (must match backend/server.py GOOGLE_SCOPES):
    openid
    https://www.googleapis.com/auth/userinfo.email
    https://www.googleapis.com/auth/calendar.readonly
    https://www.googleapis.com/auth/calendar.events
    https://www.googleapis.com/auth/gmail.readonly
    https://www.googleapis.com/auth/gmail.compose
    https://www.googleapis.com/auth/spreadsheets
    https://www.googleapis.com/auth/drive.file
  Publishing: Testing is fine while the app is in trial. Production users
  outside the test list need Google app verification. Restricted scopes
  (Gmail, Drive, Calendar) will eventually require verification / CASA.
  Do not request gmail.send or full Drive. Helm drafts mail; the user sends.

OAuth 2.0 Client ID (Web application)
  This is GOOGLE_CLIENT_ID / GOOGLE_CLIENT_SECRET on Render.
  Authorized JavaScript origins:
    https://www.helmcontrol.online
    https://helmcontrol.online
  Authorized redirect URIs:
    https://www.helmcontrol.online/api/oauth/google/callback
  Also keep Clerk's callback on the Clerk Google client (separate client):
    https://clerk.helmcontrol.online/v1/oauth_callback

API key (Browser key) — Google Picker only
  Restrict to HTTP referrers:
    https://www.helmcontrol.online/*
    https://helmcontrol.online/*
  Restrict to Picker API + Drive API.
  Paste on Render as GOOGLE_PICKER_API_KEY.
  Also set GOOGLE_CLOUD_PROJECT_NUMBER (Project number, not project id)
  from IAM & Admin → Settings. The picker will not open without both.

Service account — Document AI only
  IAM → Service accounts → Create (helm-document-ai).
  Role: Document AI API User on the processor (or Cloud Document AI User).
  Keys → Add JSON key. Do not commit the JSON.
  Paste the entire JSON as one line/env value:
    GCP_SERVICE_ACCOUNT_JSON
  Also set:
    GCP_PROJECT_ID                  (project id string)
    GCP_DOCUMENT_AI_LOCATION        us   (must match processor region)
    GCP_DOCUMENT_AI_PROCESSOR_ID    the processor id, not the display name

Document AI processor (this is what the $300 is for)
  Document AI → Create processor → Invoice Parser (or Expense Parser).
  Region: us (or the location in GCP_DOCUMENT_AI_LOCATION).
  Copy the processor ID into GCP_DOCUMENT_AI_PROCESSOR_ID.
  Helm sends uploaded bills here first. High-confidence totals skip Claude.
  Low-confidence / failures fall through to Anthropic. When credits expire,
  leave the processor; Helm still works on Claude alone if ANTHROPIC_API_KEY
  is set.

Do NOT move Render, Vercel, MongoDB Atlas, R2, Clerk, Resend, or Paddle
onto GCP to "use the credits". Those stay where they are.

---------------------------------------------------------------------------
B. What Helm does with the customer's Google Workspace
---------------------------------------------------------------------------

Trigger: workspace owner (Integrations → Connect Google). One consent
covers Calendar, Gmail, Sheets, Drive-file, and compose.

Tokens are encrypted at rest (INTEGRATION_ENCRYPTION_KEY) on the workspace
document. Helm refreshes them. If Google revokes, Helm asks reconnect.

1) Calendar read  (already live)
   Pulls primary calendar into Helm Calendar and the briefing.
   Scope: calendar.readonly

2) Calendar write  (new)
   Checkbox on Add event: "Also add to Google Calendar".
   Creates / patches / deletes the matching event on the user's primary
   calendar. Helm still stores its own copy.
   Scope: calendar.events

3) Gmail read  (already live)
   Briefing shows starred/important threads (metadata + snippet only).
   Full bodies are never written to Mongo.
   Scope: gmail.readonly

4) Gmail drafts  (new)
   Briefing → "Draft reply in Gmail" creates a Draft. Helm never sends.
   Scope: gmail.compose

5) Sheets export  (new)
   Financials → "Export to Sheets" creates a spreadsheet the user owns
   (Summary + Ledger). Helm does not keep a copy of the Sheet.
   Scope: spreadsheets

6) Drive file picker  (new)
   Financials → "From Drive" opens Google Picker, downloads only the file
   they picked, stores it in Cloudflare R2, then runs the same extract
   pipeline as a local upload.
   Scope: drive.file  (only files the user picks / that Helm created)

Existing workspaces that connected before these scopes shipped must click
Reconnect Google (Integrations) once so Google re-issues a refresh token
with the new grant. Calendar/Gmail read keep working until they do; write
features show Reconnect.

---------------------------------------------------------------------------
C. Render environment variables
---------------------------------------------------------------------------

Already required for Google Calendar/Gmail:
  GOOGLE_CLIENT_ID
  GOOGLE_CLIENT_SECRET

Add for the new product features:
  GOOGLE_PICKER_API_KEY              browser API key (Picker)
  GOOGLE_CLOUD_PROJECT_NUMBER        numeric project number (Picker app id)

Add to spend GCP credits on invoice parsing:
  GCP_PROJECT_ID
  GCP_DOCUMENT_AI_LOCATION           default us
  GCP_DOCUMENT_AI_PROCESSOR_ID
  GCP_SERVICE_ACCOUNT_JSON           full service-account JSON

Optional (not used in code; do not set unless you later wire Vertex):
  Vertex AI / Gemini — postponed. Anthropic remains the product LLM.
  Document AI is the GCP spend.

---------------------------------------------------------------------------
D. What we explicitly do not use
---------------------------------------------------------------------------

  - gmail.send              Helm must not send as the user
  - drive (full)            too sensitive; picker uses drive.file
  - Google Tasks            Helm has its own Tasks board
  - Chat / Meet SDK         Calendar already shows Meet links in events
  - Maps, Ads, Analytics 4  not part of the cockpit
  - Identity Platform       Clerk is sign-in
  - Cloud Run / GCE / SQL   hosting stays on Render + Vercel + Atlas
  - Workspace Directory     invite-company-from-Google — later, not built

---------------------------------------------------------------------------
E. Quick check after paste
---------------------------------------------------------------------------

1. Redeploy the Render API.
2. curl -H "X-Setup-Secret: YOUR_SETUP_SECRET" \
     https://www.helmcontrol.online/api/setup/status
   Look at integrations.google_calendar.configured and
   integrations.document_ai.configured.
3. In the app: Integrations → Reconnect Google (accept all scopes).
4. Financials: Export to Sheets, From Drive, upload a bill (Document AI
   then Claude).
5. Calendar: add an event with "Also add to Google Calendar".
6. Briefing: Draft reply in Gmail — confirm it is a draft, not sent.

Code entry points
  backend/google_oauth.py          Calendar, Gmail, Sheets, Drive user APIs
  backend/google_document_ai.py    Invoice Parser (service account)
  backend/llm.py                   extract_financial_document orchestration
  backend/server.py                GOOGLE_SCOPES + HTTP routes
  frontend/src/lib/googlePicker.js Drive picker
